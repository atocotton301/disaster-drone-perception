# 검증결과 — 2026-09-14 Windows

**구현됨: 실제 센서/ROS 처리 코드, 한 번 실행, 화면, 상태 차단, 기록. 미확인: Jetson+D435i 실물 통합 및 실제 5종 모델 추론.**

## 실행한 검증

- Python 소스 전체 compileall 문법 검사 통과.
- unittest 14개 통과: 깊이 단위·무효값, 정렬/프레임/시간차 거부, LOST/STALE, 비정상 covariance/회전 거부, 지도 원점 회전·y 반전, 화염/연기 거리 미확정, 비누적 투영, 높이·설정, TUM 일대일 시각 연결 및 경로 검사. 실제 게이트 콜백에 메시지 fixture를 넣어 정상 프레임만 전달하고 실패·중복·지연 프레임을 차단함도 검사했습니다. 이 콜백 검사는 ROS 전송 시험이 아닙니다.
- TUM Kinect 실측 fr1/xyz 원본 TGZ 다운로드·추출. SHA-256: `a0236d97b8c30cd93b653656d2b6c293ff7c982a4130ef2a1a8beecdb124ef98`.
- 실측 RGB-D 640×480 이미지 60쌍을 읽어 처리. 유효 깊이 픽셀 222,480~236,609개, stride=4 투영점 13,947~14,827개, 카메라 기준 점유 격자 177~681개. 시각 차이는 절대값 최대 14.897ms. 이는 해당 데이터 처리 결과이며 정확도나 Jetson 성능 수치가 아닙니다.
- 실제 Tk 창에 공개 기록을 연결하여 5프레임 처리 및 이미지·Depth 저장, 종료 확인. 모델이 없으므로 탐지 0건이며, 누적 지도·위치·궤적은 생성하지 않는 것을 확인.
- 입력 없는 화면 실행·자동 종료 통과. Windows에서 실제 ROS 실행을 요청하면 미설치 ROS/카메라 패키지와 미확인 장착 변환을 보고하고 중단함을 확인.
- 카메라 없는 저장 세션 재열람 통과. Headless 실행 후 로컬 stop 명령으로 정상 종료 확인.
- Windows에서 실측 입력 headless 기록을 실행한 뒤 `--source session --latest`로 기록 정상 종료→최근 세션 열람→창 종료까지 통과. Linux ROS 자식 프로세스/DB 마감은 Jetson 검증 대상입니다.
- 느린 재생 수정 확인: 3.016초 실행 중 처리 로그의 원본 시각이 2.468초 진행. 5Hz 작업 때문에 원본 30Hz 영상을 약 6배 느리게 재생하던 직렬 구조를 분리했습니다. 시작·종료 및 처리 샘플 간격을 포함한 시험이며 하드웨어 프레임률 측정은 아닙니다.
- 최종 작업 전용 Windows 가상환경: Python 3.12, NumPy 2.2.6, OpenCV contrib headless 4.12.0, Pillow 12.3.0. OpenCV odometry API를 사용하는 가상 시험을 위해 이 프로젝트 전용 환경만 조정했습니다. 기존 학습 환경과 Jetson CUDA/torch는 변경하지 않았습니다.

## 별도 가상환경 시험 — 실측 시험과 구분

사용자 요청에 따라 가상 실내를 ray casting으로 촬영한 RGB·Depth 180쌍을 생성했습니다. OpenCV RgbdICPOdometry가 입력 영상·깊이로 이동을 추정하고 5cm 점유 격자를 누적합니다. 렌더러의 정답 이동 경로는 지도 생성에 전달하지 않고 오차 평가에만 사용했습니다.

180프레임 중 LOST 0회, 최종 점유 셀 1,068개, 이상적인 무잡음 가상 조건에서 마지막 위치 오차 약 0.001m였습니다. 이 오차는 실제 센서 성능 수치가 아닙니다. 루프 폐쇄와 YOLO는 수행하지 않았습니다. `simulation/virtual_mapping.mp4`는 H.264, 1280×720, 15fps, 12초이며 180프레임 전체 디코딩을 확인했습니다. 보고서는 `simulation/simulation_report.json`입니다.

## 증거 파일

- `validation/public/public_validation.json`: 원본 URL/checksum/프레임별 결과.
- `validation/gui/gui_result.json`: 창·실제 프레임·기록·종료 검증.
- `validation/gui/actual_window.png`: 공개 RGB-D를 띄운 실제 프로그램 창. 누적 SLAM 영역은 비어 있음.
- `validation/windows_environment.json`: ROS/모델/장착값 미확인 보고서.

## 아직 검증할 수 없는 부분

ROS 2 / RTAB-Map 실행, IMU 초기화, RealSense firmware/USB 정렬, ROS QoS 실제 전달, timestamp TF, 루프 폐쇄, 실제 장착 extrinsic, GPU 추론 및 전시 처리율, 5종 탐지 정확도, 실측 거리 오차는 장비/모델이 없어 미검증입니다. ROS 소스의 문법 검사와 수학·상태 테스트는 실물 통합 시험을 대체하지 않습니다.

TUM은 원본 실측 시각을 보존해 연결합니다. 가상환경 데이터는 별도 metadata에 SIMULATED_CLOCK으로 표시합니다. 초기 Redwood 샘플은 합성 환경 계열임을 확인해 실측 검증 자료에서 제외했습니다. 실제 벽·장애물 비교 시험은 README의 Jetson 합격 확인 순서대로 수행해야 합니다.
