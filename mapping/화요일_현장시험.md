# 화요일 오전 · 한성대 공학관 현장 시험

목표: Jetson 단독으로 카메라 영상을 받고 지도까지 저장한 후, Jetson에 별도 모니터를 연결해 결과 확인.

## 출발 전 한 번

1. `disaster_system` 폴더를 Jetson에 복사.
2. Ubuntu / JetPack / RAM / ROS 환경 확인 및 README의 필요한 의존성 준비.
3. 카메라 장착 변환을 실측하여 `config.json` 수정. 기본 1m는 예시값. 실측 후 `mount_verified=true`.
4. 모델이 있으면 `weights`에 Jetson 로컬 best.pt 경로. 아직 없으면 빈 문자열로 깊이·지도부터 시험.
5. 모니터에서 `bash start_jetson.sh --check`로 점검. 실제 CUDA 확인 전 `device=cpu` 유지.

## 현장 시작

카메라 USB 연결, 저장 공간·전원 확인 후:

```bash
source /opt/ros/humble/setup.bash  # 설치된 실제 배포판에 맞게 변경
bash start_jetson.sh --headless
```

처음 시험은 모니터를 켠 일반 모드 `bash start_jetson.sh`로 RGB·Depth·TRACKING이 들어오는지 먼저 확인하는 것이 좋습니다. 자동비행·자동복귀·원격 연결은 사용하지 않습니다.

장치를 움직일 수 있다면 느리게 짧은 직선과 왕복부터 기록합니다. 움직일 수 없다면 TUM 또는 가상 RGB-D 재생으로 입력 경로를 검사하되, 공학관 지도를 만들었다고 설명하지 않습니다.

## 회수 후

Jetson 전원을 유지한 채 별도 모니터를 연결하고 키보드·마우스로:

```bash
bash view_results.sh
```

이 명령은 기록을 마감한 뒤 최근 결과를 엽니다. PC 연결·파일 전송 불필요. 화면의 지도·궤적·RGB/Depth를 확인하고 상세 기록은 `runs/날짜_시각/`에 있습니다.

## 꼭 남길 실제 확인

- 모서리·벽·장애물이 지도와 대략 대응하는지.
- 카메라를 가렸을 때 LOST/STALE이 표시되고 새 지도 입력이 차단되는지.
- 불투명 물체를 알려진 거리에서 측정한 오차.
- 정상 종료 후 DB·지도·프레임·탐지 로그가 남는지.

처음 장비를 연결하기 전에는 ‘연결만 하면 검증 완료’ 상태가 아닙니다. 이 현장 시험을 통과해야 전시용 실물 통합 완료로 볼 수 있습니다.
